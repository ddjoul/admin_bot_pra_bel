# Админ-бот пра.бел

Отдельный Telegram-бот. Создай НОВЫЙ токен через @BotFather /newbot.
Не используй токен публичного бота приёма произведений: публичный бот работает
через webhook, а этот — через polling. Они должны быть разными ботами.

Доступ только ADMIN_TELEGRAM_ID=5710647144 и только в личном чате.
Чужие сообщения игнорируются, чужие кнопки отклоняются.
Telegram ID не секрет; ключи Supabase и токен — секреты.

1. Просмотри setup_admin.sql и выполни в Supabase SQL Editor.
   Он добавляет rejected в справочник статусов произведений, если его ещё нет.
   Существующие строки и настройки доступа не удаляет.
2. Скопируй .env.example в .env и заполни токен нового бота и серверный ключ.
3. Python 3.11+:
   python -m venv .venv
   Windows PowerShell:
   .venv\Scripts\python -m pip install -r requirements.txt
   .venv\Scripts\python admin_bot.py
   Linux:
   .venv/bin/python -m pip install -r requirements.txt
   .venv/bin/python admin_bot.py
4. Открой НОВОГО бота в Telegram, отправь /start.

/comments или комментарии: 5 pending комментариев за раз, весь текст.
/posts или стихи / переводы: 5 draft произведений категорий poem/translation.
/stats: количество ожидающих записей.
После просмотра Опубликовать/Отклонить бот повторно показывает запись
и просит подтвердить. При изменении содержимого необходимо просмотреть заново.
Статусы и status_id получаются из справочников. Публикация произведения
заполняет published_at; отклонение ставит rejected и published_at=null.
Отклонение НЕ удаляет произведение/комментарий.
Публичная SELECT-политика posts, предоставленная пользователем, показывает
только published. Для comments тоже требуется включённый RLS и чтение только
published; их текущие политики не были предоставлены и здесь не изменяются.

Личные уведомления отправителям и автоматическое оповещение о новых записях
не реализованы: обновляй очередь кнопками. После решений обновляй список
с начала: номера страниц смещаются по мере уменьшения очереди.
Этот бот не одобряет пользователей для автоматической публикации: это по-прежнему
telegram_users.is_approved в Supabase. Одобренные отправители обходят очередь draft
по прежним правилам публичного бота.

Требуется один запущенный процесс. Когда компьютер выключен, админ-бот не работает,
но публичный бот и сайт продолжают работать. Бесплатный Render Web Service
не подходит для ЭТОГО polling-файла: он не слушает HTTP-порт.
Не публикуй .env или ключи в GitHub. .gitignore не скрывает уже закоммиченные файлы.

Проверен только синтаксис Python; Telegram, Supabase и существующие триггеры
нужно проверить на тестовых комментариях/произведениях перед реальной модерацией.
